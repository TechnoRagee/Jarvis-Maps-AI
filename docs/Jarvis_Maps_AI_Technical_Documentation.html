1. Executive Architecture Overview

Jarvis Maps AI is an enterprise-grade autonomous geospatial boundary extraction and computer vision analysis system. The platform automates the discovery, visual capture, pixel-level contour reconstruction, and geographic transformation of administrative and locality boundaries directly from Google Maps satellite and vector cartography.

Key Technical Capabilities

  • 100% Zero-Selenium Engine: Pure Playwright asynchronous and synchronous driver integration with native mouse drag, gesture zoom, and DOM event dispatching.
  • Adaptive Multi-Zoom Scanning: Multi-resolution boundary probing (Zoom 15 → 14 → 13) to capture sprawling localities and micro-sectors with zero edge truncation.
  • Dual Computer Vision Pipelines:
    • Primary: Google-Red Color Space Segmentation, Polar Ray Snapping, and Target-Guided Shortest-Path Graph Search (OpenCV).
    • Secondary Fallback: Deep learning Segment Anything Model (SAM) with ViT image embeddings for ambiguous or unoutlined regions.
  • DPR-Aware Web Mercator Mathematical Georeferencing: Converts raw screenshot canvas pixels to exact WGS84 Geographic Coordinates (EPSG:4326) with sub-meter accuracy.
  • Terrain-Clamped KMZ with GroundOverlay: Packages vector boundaries with embedded satellite imagery overlays, allowing 1:1 visual verification in Google Earth Pro.

3. Core Technical Pipeline & Algorithms

3.1 Playwright Browser Automation & UI Management

Google Maps relies on dynamic JavaScript rendering, client-side WebGL canvas drawing, and asynchronous drawer cards. The automation layer in playwright_pipeline.py solves browser-level challenges through:

  • Viewport Configuration: Standardized viewport dimensions (1540 × 732 px) configured at Device Pixel Ratio 1.25, producing an exact 1925 × 915 px full-resolution screenshot buffer.
  • Active Drawer Suppression (close_maps_ui): Queries and clicks button[aria-label*="Collapse side panel"], button[jsaction*="drawer.close"], and forces CSS inline property overrides (display: none !important) on left search cards (#pane, .widget-pane, .w6VYqd). This prevents occlusion of western boundaries.
  • Native Multi-Zoom Stepping: Visual zooming without URL reload using Playwright's native mouse wheel (page.mouse.wheel(0, ±350)), keyboard triggers (Equal / Minus), and on-screen zoom control clicks, coupled with camera URL hash polling (@lat,lng,zoomz).

3.2 OpenCV Boundary Extraction & Graph Reconstruction

Google Maps indicates search locality boundaries with a distinctive red/magenta dotted outline. The vision extraction pipeline isolates and reconstructs these lines through four mathematical stages:

HSV & RGB Color Segmentation Formula:
Pixels are classified as boundary candidates if they satisfy the strict red hue and saturation constraints:
Strict Mask = (H ∈ [340°, 20°]) ∧ (S ≥ 0.40) ∧ (V ≥ 0.45) ∧ (R > G + 35) ∧ (R > B + 35)
  1. Morphological Filtering: Removes standalone text labels, restaurant/store circular icons, and UI artifacts while preserving thin line connectivity.
  2. Graph Representation: Converts remaining red pixel components into a mathematical network graph $G = (V, E)$. Endpoints within Euclidean gap distance $D_{gap} \le 40 ext{px}$ are connected via weighted shortest paths.
  3. Polar Coordinate Snapping: Projects rays from the searched place centroid $(x_c, y_c)$ across $360^\circ$ at angular resolution $\Delta heta = 1.33^\circ$ (270 bins). Radial bin peaks are snapped directly to valid red pixel clusters.
  4. Exact Micro-Contour Preservation: Converts the snapped contour into WGS84 coordinates with epsilon threshold $\epsilon = \max(0.05, P imes 0.00004)$ and maximum vertex limit of $1500$, preserving all 500+ true road and highway curve points.

4. Mathematical Georeferencing Specification

To transform pixel coordinates $(X_{px}, Y_{px})$ on the screenshot image to Geographic Latitude and Longitude $(\phi, \lambda)$ in WGS84 (EPSG:4326), the system implements an exact DPR-corrected Spherical Mercator projection.

4.1 Forward Projection (Pixels → Lat/Lng)

Given the Google Maps camera center $(\phi_c, \lambda_c)$ and zoom level $Z$:

# 1. Compute World Coordinates of Camera Center (Zoom level 0 pixel space: 256x256)
world_x_center = (lng_center + 180.0) / 360.0 * 256.0
sin_lat = sin(radians(lat_center))
world_y_center = (0.5 - log((1.0 + sin_lat) / (1.0 - sin_lat)) / (4.0 * pi)) * 256.0

# 2. Scale Screenshot Pixels to CSS Display Pixels via DPR
css_x = (pixel_x - image_center_x) * (1.0 / DPR)
css_y = (pixel_y - image_center_y) * (1.0 / DPR)

# 3. Compute Target Point in World Coordinate Space
world_x = world_x_center + (css_x / (256.0 * 2^Z)) * 256.0
world_y = world_y_center + (css_y / (256.0 * 2^Z)) * 256.0

# 4. Inverse Mercator Projection to WGS84 Degrees
longitude = (world_x / 256.0) * 360.0 - 180.0
n = pi - 2.0 * pi * (world_y / 256.0)
latitude = degrees(atan(sinh(n)))

4.2 Ground Resolution & Scale

The ground resolution at latitude $\phi$ and zoom level $Z$ is calculated as:

$$S = rac{156543.03392 imes \cos(\phi)}{2^Z imes ext{DPR}} \quad \left[ rac{ ext{meters}}{ ext{pixel}} ight]$$
Example (Vaishali, Lat 28.64°, Zoom 15.03, DPR 1.25): Ground resolution = 3.28 meters / pixel.

KMZ with GroundOverlay .kmz Google Earth Pro 3D visual verification Bundled zip archive containing the vector polygon (doc.kml) plus the raw georeferenced satellite image (overlay.png) mapped to exact <LatLonBox> coordinates.

5.1 Google Earth Pro 1:1 Verification Workflow

  1. Double-click the generated <Query>.kmz file to open it in Google Earth Pro.
  2. Under the Places panel, you will see both the Google Satellite Imagery Overlay and the Vector Boundary.
  3. Adjust the Transparency Slider on the GroundOverlay layer to confirm 0-pixel displacement between Google's red outline and the vector polygon vertices.

6. Maintenance, Diagnostics & API Integration

6.1 Python API Usage

To integrate Jarvis Maps AI into custom automation pipelines, import export_boundary from utils.boundary_extractor:

from utils.boundary_extractor import export_boundary

# Execute automated extraction
result = export_boundary(
    query="Vaishali, Ghaziabad, Uttar Pradesh",
    output_dir="boundaries"
)

if result["status"] == "Success":
    print(f"Extraction Successful! Extracted {result['polygon_points']} points.")
    print(f"KML Path: {result['kml_path']}")
    print(f"KMZ Path: {result['kmz_path']}")
    print(f"GeoJSON Path: {result['geojson_path']}")
    print(f"GeoTIFF Path: {result['geotiff_path']}")
else:
    print(f"Extraction Failed: {result['error']}")

6.2 Diagnostic Reports & Failure Recovery

When an extraction encounters challenging terrain or ambiguous boundaries, comprehensive JSON reports are generated in boundaries/reports/:

  • *_georef_report.json: Mathematical debug dump of camera world coordinates, scaling factors, bounding box corners, and pixel conversion metrics.
  • *_overlap_report.json: Comparison against existing stored boundaries checking for duplicate or intersecting polygons.
  • *_adaptive_locality_report.json: Record of multi-zoom attempts, polar ray distributions, and candidate contour scoring.
